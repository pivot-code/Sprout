# 概念对比

## 什么时候用

当用户提出以下类型的需求时使用：

- "对比 A 和 B"
- "A 和 B 有什么区别"
- "A 和 B 哪个好"
- "帮我区分一下 A 和 B"
- "A 和 B 有什么不同"

只要用户想**区分两个概念**，就用这个 skill。

## 怎么用

调用 `compare_concepts` 工具，参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `concept_a` | 是 | 第一个概念 |
| `concept_b` | 是 | 第二个概念 |
| `course_name` | 否 | 如果提供了，会从这门课的笔记里找依据；留空则用通用知识 |
| `save` | 否 | 是否保存到 `comparisons/`，默认 true |

### 关于 course_name

- 用户说"从我的计算机网络笔记里对比" → 填课程名
- 用户没提课程 → 留空
- **如果留空，对比会基于 LLM 的通用知识**，这在大部分情况下是够用的

## 输出

工具会把对比文档保存到：

- `comparisons/{A}_vs_{B}.md`

并在对话里返回全文。

**你应该：**

- 把对比全文展示给用户（它是为用户生成的核心内容）
- 告诉用户保存在哪

## 示例

**例 1：直接对比**

用户："对比 TCP 和 UDP"

做法：调用 `compare_concepts`，`concept_a="TCP"`，`concept_b="UDP"`。

**例 2：从某门课的资料对比**

用户："从我的计算机网络笔记里对比 TCP 和 UDP"

做法：调用 `compare_concepts`，`course_name="计算机网络"`。

**例 3：不保存**

用户："就说说 A 和 B 的区别，不用存"

做法：调用 `compare_concepts`，`save=false`。

## 注意

- 对比文档是给用户看的，**全文展示，不要截断**
- 如果用户对比的是两个差别很大的概念（比如"苹果和汽车"），如实对比，不要硬凑
- 不要主动调用本工具。用户没要求对比时，不要动
