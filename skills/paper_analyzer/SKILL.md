# 论文解读

## 什么时候用

当用户提出以下类型的需求时使用：

- "帮我解读这篇论文"（配合上传的 PDF）
- "这篇论文讲了什么"
- "总结一下这个 PDF"
- "这篇论文值不值得读"
- 用户上传一个 PDF 并问"这是什么"

只要用户想**理解一篇论文 PDF**，就用这个 skill。

## 怎么用

调用 `analyze_paper` 工具，参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `file_path` | 是 | PDF 路径 |
| `depth` | 否 | `full`（默认）完整解读；`brief` 快速判断 |
| `save` | 否 | 是否保存到 `papers/`，默认 true |

### 关于 file_path

用户上传 PDF 后，系统会把它保存到 `uploads/{session_id}/` 下。你需要：

- 如果用户上传了文件，路径通常是 `uploads/{session_id}/{文件名}`
- 如果用户说了一个路径，直接用那个路径
- 如果不确定，先用 `terminal` 搜一下

### 关于 depth

- 用户说"简单说说""值不值得读" → `brief`
- 用户说"详细解读""帮我理解" → `full`
- 用户没说 → 默认 `full`

## 输出

工具会把解读保存到：

- `papers/{文件名}_解读.md`

并在对话里返回预览。

**你应该：**

- 把解读内容展示给用户（它是核心产出）
- 告诉用户保存在哪
- 如果用户想做进一步操作（比如对比、深入某个部分），引导他

## 示例

**例 1：上传 PDF 后解读**

用户："帮我解读这篇论文"（附带 PDF）

做法：先确认 PDF 上传后的路径（通常在 `uploads/{session_id}/` 下），
调用 `analyze_paper(file_path="...")`。

**例 2：快速判断**

用户："这篇论文值不值得读？"（附带 PDF）

做法：调用 `analyze_paper(file_path="...", depth="brief")`。

**例 3：指定路径**

用户："帮我解读 papers/my_paper.pdf"

做法：调用 `analyze_paper(file_path="papers/my_paper.pdf")`。

## 注意

- **只处理 PDF**。如果是 Word、PPT 等其他格式，用 `read_rich_file` 而不是这个工具
- 扫描版 PDF（图片型）无法提取文字，工具会报错。告诉用户"这篇 PDF 是扫描件，提取不到文字，建议找文字版"
- 超长 PDF（超过 20000 字符）只解读前部分，工具会在输出里说明
- 解读内容是给用户看的，**全文展示，不要截断**
- 不要主动调用本工具。用户没要求解读论文时，不要动
