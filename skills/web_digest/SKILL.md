# 网页内容消化

## 什么时候用

当用户提出以下类型的需求时使用：

- "帮我总结这个网页"
- "把这个链接整理成笔记"
- "这篇文章讲了什么"
- "消化一下这个 URL"
- 用户直接贴出一个网页链接并问"这讲什么"

只要用户想**把一个网页的内容变成可读的笔记**，就用这个 skill。

## 怎么用

调用 `digest_web_page` 工具，参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `url` | 是 | 网页链接，必须以 `http://` 或 `https://` 开头 |
| `title` | 否 | 可选标题，留空则从网页自动提取 |
| `detail_level` | 否 | `full`（默认）输出结构化笔记；`brief` 只输出 200 字概括 |
| `save` | 否 | 是否保存到 `digests/`，默认 true |

### 关于 detail_level

- 用户说"简单说说""概括一下" → `brief`
- 用户说"整理成笔记""详细一点" → `full`
- 用户没说 → 默认 `full`

### 关于 save

- 用户说"保存""存起来" → `save=true`（默认）
- 用户说"就说说，不用存" → `save=false`
- 用户没说 → 默认 `true`

## 输出

工具会把笔记保存到：

- `digests/{日期}_{标题}.md`

并在对话里返回预览。

**你应该：**

- 告诉用户笔记保存在哪
- 把预览里的关键信息转述给用户
- 不要直接贴整个笔记（太长）

## 示例

**例 1：用户贴了链接**

用户："帮我总结一下 https://example.com/article"

做法：调用 `digest_web_page`，`url` 填链接。

**例 2：用户只想快速了解**

用户："这篇文章讲什么？简单说说 https://..."

做法：调用 `digest_web_page`，`detail_level` 填 `brief`。

**例 3：用户不想存**

用户："就给我说说这个网页，不用存文件 https://..."

做法：调用 `digest_web_page`，`save` 填 `false`。

## 注意

- 一次只处理**一个网页**。用户给多个链接时，分别调用
- 有些网页是动态渲染的（比如知乎、微信公众号），工具可能抓不到内容。遇到这种情况，告诉用户"这个网页可能需要登录或者是动态加载的，我抓不到内容，你可以把正文复制给我"
- 不要主动调用本工具。用户没要求消化网页时，不要动
- 不要自己写笔记文件，一律走这个工具
