# 学习报告生成

## 什么时候用

当用户提出以下类型的需求时使用：

- "生成一份学习报告"
- "我最近学了什么"
- "总结一下今天的活动"
- "这周有什么进展"
- "帮我看看最近的学习情况"

## 怎么用

调用 `generate_study_report` 工具，参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `hours` | 否 | 统计过去多少小时，默认 24 |
| `save` | 否 | 是否保存到 `reports/`，默认 true |

### hours 怎么填

- 用户说"今天""最近一天" → `hours=24`（默认）
- 用户说"这周""最近一周" → `hours=168`
- 用户说"最近三天" → `hours=72`
- 用户没说 → 默认 24

### 关于 save

- 用户没说 → 默认 `true`，保存到 `reports/`
- 用户说"不用存" → `save=false`

## 输出

工具会：

1. 扫描 `courses/`、`arxiv_papers/`、`memory/logs/` 下的近期变化
2. 调用 LLM 生成报告
3. 保存到 `reports/{时间戳}.md`
4. 返回报告全文

**你应该：**

- 把报告全文展示给用户（报告本身就是给用户看的）
- 如果保存了，告诉用户保存在哪
- 如果报告里有"建议"部分，可以稍作解释

## 示例

**例 1：标准用法**

用户："生成一份今天的学习报告"

做法：调用 `generate_study_report`，参数用默认值（`hours=24`，`save=true`）。

**例 2：周报**

用户："帮我总结一下这周的学习情况"

做法：调用 `generate_study_report`，`hours=168`。

**例 3：不保存**

用户："随便说说我最近学了什么，不用存"

做法：调用 `generate_study_report`，`save=false`。

## 注意

- 报告是给用户看的，**全文展示，不要截断**
- 报告里的数据来自真实的文件扫描，不要自己编造数字
- 如果用户没要求生成报告，不要主动调用本工具
- 定时推送未来会做，现在是手动触发
